# Believable mock data and photographs for the fishing log seed

**Recommendation:** Download a fixed, verified list of about 50 Unsplash photographs once into `packages/client/public/seed/` and commit them, rather than hotlinking or uploading to R2. Downloading from the website (not the API) sits under the plain Unsplash License, which requires no attribution and explicitly permits copying and distribution, while the API route would bind us to hotlinking, attribution and download-event obligations forever. Then rewrite `prisma/seed.ts` as a guarded, id-deterministic, idempotent script over eight anglers, fifteen verified Western Cape spots, ten real species with weights computed from FishBase length-weight parameters, and fifty catches dated to real Cape Town sunrise and sunset times.

**Effort:** M. About 1,200 lines of data literals and 300 lines of script across fourteen new files, one five-line change to uploads.service.ts, and one manual photo download pass. No schema change and no migration are needed for the core seed, which is what keeps it M. It becomes L only if the owner wants blank trips and the club competition seeded for real, since both need new models, and the repo has neither.

## Repo changes
- `packages/server/prisma/seed.ts`: Replace all 96 lines. Becomes a thin entry point: assert the environment guard, then call the seeders in dependency order (species, anglers, spots, gear, catches, images, feed, social), then print a one-line summary. Every current row goes away: 'Sunrise Pier' at 32.7157/-117.1611 is in San Diego, the species is a Californian halibut, and the two users are 'Angler One' and 'Angler Two'.
- `packages/server/prisma/seed/guard.ts`: New. Three independent refusals before any write: refuse if NODE_ENV === 'production'; refuse unless the DATABASE_URL host is localhost or 127.0.0.1, or SEED_ALLOW_REMOTE_HOST matches it exactly; refuse unless the database name is in an allowlist (fishing_app, fishing_app_dev, fishing_app_test). Prints the host and database it is about to write to and requires SEED_CONFIRM=yes for any non-local host. There is no existing guard anywhere in the repo, and packages/server/.env currently points DATABASE_URL at a real database.
- `packages/server/prisma/seed/ids.ts`: New. Deterministic id helper, seedId(kind, slug) returning `seed_<kind>_<slug>`. Every seeded row gets an explicit id so every write is an upsert on a stable key and re-running changes nothing. This is required because Species, Catch, FishingSite, Gear, Comment, FeedPost and FeedComment have no natural unique key, only cuid defaults.
- `packages/server/prisma/seed/data/anglers.ts`: New. Eight angler literals: id, clerkId (seed_ prefixed so they can never collide with a real Clerk subject through userService.syncAuthenticatedUser), email on the reserved .invalid TLD, username, displayName, bio under the 280 character limit that user.schema.ts enforces, and avatarUrl pointing at /seed/anglers/<name>.jpg.
- `packages/server/prisma/seed/data/spots.ts`: New. Fifteen FishingSite literals with verified latitude and longitude, waterType, description and accessNotes within the 500 character limit in fishing.schema.ts.
- `packages/server/prisma/seed/data/species.ts`: New. Ten Species literals with commonName, scientificName, aliases Json (for example galjoen: ['damba', 'black bream']) and regionTags Json (['western-cape', 'false-bay', 'west-coast']). The Species table currently holds one Californian halibut row and both Json columns are unused.
- `packages/server/prisma/seed/data/gear.ts`: New. Sixteen Gear literals across the seven GearType enum values using real South African brands and verified model names (Assassin, Poseidon, Sensation, Kingfisher) plus the international brands actually sold here (Daiwa, Shimano, Penn, Mustad). imageUrl points at /seed/gear/<name>.jpg.
- `packages/server/prisma/seed/data/catches.ts`: New. Fifty catch literals: angler, spot, species, caughtAt anchored to the verified sunrise and sunset for that month, length in cm, released or kept, title and notes in the brief's voice, and a conditions key naming one of the named weather profiles.
- `packages/server/prisma/seed/lib/weight.ts`: New. weightKg(species, lengthCm) implementing the FishBase relation W(g) = a * L(cm)^b with the per-species a and b constants, rounded to two decimals. This is what stops a 44 cm elf being recorded at 6 kg; length and weight can never contradict because only length is authored.
- `packages/server/prisma/seed/lib/conditions.ts`: New. Eight named Cape weather profiles (march-southeaster, april-calm, may-front-edge, june-northwester, july-cold-front, august-easing, september-southwester, dam-still) that expand into the twenty-five weather columns on Catch, with weatherIsDaytime derived from the catch time against that date's sunrise and sunset, weatherCurrentTime set to the catch hour and weatherTimeZoneId 'Africa/Johannesburg'. weatherConditionIconBaseUri stays null deliberately, because guessing Google's icon base URI produces a broken image and the client renders weatherConditionText anyway.
- `packages/server/prisma/seed/data/social.ts`: New. Sixteen Follow rows including two mutual pairs, about ninety CatchLike rows, forty Comment rows, eight Review rows and the matching FeedLike and FeedComment rows, each with an explicit id. Also sets the denormalised likeCount, commentCount, reviewCount and catchCount columns to match the rows actually written, since every list surface reads the counters rather than counting.
- `packages/server/prisma/seed/data/photos.ts`: New. The photo manifest: local path, Unsplash photo id, photographer name and username, and the images.unsplash.com file URL, for the 44 verified ids. Read by both the downloader and the seeder.
- `packages/server/prisma/seed/fetch-photos.ts`: New, run once by hand and not part of the seed. Walks the manifest, fetches each file URL with ?w=1200&fm=jpg&q=70&fit=max (avatars at ?w=600&h=600&fit=crop&crop=faces&q=75), writes into packages/client/public/seed/, and regenerates CREDITS.md. Verified against three live URLs: they return image/jpeg at 178 KB, 469 KB and 37 KB respectively.
- `packages/server/services/uploads.service.ts`: One change, about five lines, at the top of getReadUrl: if the storageKey starts with 'seed/', return { storageKey, readUrl: `/${storageKey}` } without touching R2. This is load-bearing. withResolvedImageUrls in fishing.service.ts:286-327 and withResolvedFeedImageUrls in feed.service.ts:44-101 call getReadUrl for every catch and site image and overwrite image.url with the result, so seeded photo URLs are discarded the moment R2 credentials are present. Today packages/server/.env has CLOUDFLARE_ACCOUNT_ID but no CLOUDFLARE_R2_ACCESS_KEY_ID, so getConfig() throws, the catch falls back to the persisted URL, and seeded images would happen to work. Adding the missing R2 keys, which .env.example tells everyone to do, silently breaks every seeded photo. Fixing it in getReadUrl fixes all three call sites at once.
- `packages/client/public/seed/`: New committed directory, about 50 JPEG files in anglers/, catches/, spots/ and gear/, roughly 7 MB total. Served by Vite at /seed/... exactly as the existing seven files under public/photos/ are served at /photos/...
- `packages/client/public/seed/CREDITS.md`: New. One line per photograph: local filename, photographer name, Unsplash profile link and photo link. Not legally required under the Unsplash License for website downloads, but it costs nothing, it is what the photographers ask for, and it is the only record of where these files came from. The seven existing photos under public/photos/ have no provenance record at all: the commit that added them carries an unrelated message about radix dependencies, and there is no credits or licence file anywhere in the repo.
- `packages/server/package.json`: Add two scripts: 'seed:photos': 'bun run prisma/seed/fetch-photos.ts' and 'seed:reset': 'bun run prisma/seed.ts --reset'. The existing 'prisma:seed' and the prisma.seed hook keep working unchanged.
- `packages/server/prisma/seed/data/trips.ts`: New but inert. Fourteen blank trip literals written against the Trip model that gap C1 specifies and that does not exist yet. The seeder skips this file unless 'trip' in prisma, so it costs nothing today and the data is already written when C1 lands. Same pattern for a club and competition, which have no model anywhere in the repo: grep for competition, fishing club and leaderboard across docs, client and server returns zero hits.

## Risks
- The seeded feed is visible to every real signed-in user, not just to the seed accounts. feed.service.ts listFeed has no author filter and every seeded catch creates a GLOBAL FeedPost, mirroring what fishing.service.ts:443-451 does on a real save. On a shared or staging database, fifty fabricated catches by eight fabricated anglers become the public feed for whoever signs in. Mitigation: the environment guard refuses non-local hosts by default, and the app should carry the prototype's own line, 'Sample data. Unsplash photographs stand in for the angler's own.'
- The photo URL rewrite is a silent breakage rather than a loud one. Because withResolvedImageUrls catches its own error and falls back, seeded photos work today on a machine with no R2 keys and stop working on a machine that has them, with only a console warning. If the getReadUrl change is skipped, the seed will look correct for whoever writes it and broken for whoever reviews it.
- The photographs are not South African species, not South African coastline in most cases, and not the seeded anglers. A held bass photographed in Michigan sitting under a record that reads 'Galjoen, 45 cm, Kalk Bay' is a small lie the interface is telling. It is acceptable for seed data only while the interface says so in words, and it becomes a real problem if a screenshot of it is ever used in marketing.
- Two of the ten species are IUCN Endangered: dusky kob (assessed 2018) and white steenbras (assessed July 2024). Seed rows that show them kept rather than released read badly to an angling audience that knows the regulations. The seed marks them released, but the released flag is gap B5 and does not exist in the schema yet, so today it can only live in the notes text.
- Idempotency is only as good as the id discipline. Every model except User, Follow, CatchLike, SiteLike, FeedLike, Review and the image junctions has no unique key other than its cuid primary key, so a seeder that forgets an explicit id on one Comment or FeedPost will duplicate that row on every run and quietly inflate the counters it also writes.
- The denormalised counters can drift. The seed writes likeCount, commentCount, reviewCount and catchCount directly to match the rows it creates. If a later partial re-run writes rows without recomputing counters, the surfaces that read counters will disagree with the surfaces that count rows, and the first symptom will be a feed post claiming comments that do not render.
- Lakenvlei could not be verified. The brief names it as a sample dam and the prototype shows 'Lakenvlei, 31 cm', but neither Wikipedia nor OpenStreetMap returns a Western Cape water by that name; the only match is in Mpumalanga. Rather than invent coordinates, the seed omits it and omits trout with it, which removes one of the ten species the brief asked for.
- Committing roughly 7 MB of JPEG into the repo is permanent. Git keeps the blobs even if the files are later deleted, and swapping a photograph adds its replacement rather than replacing it.
